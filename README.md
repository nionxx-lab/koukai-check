# 公開前チェック（koukai-check）

**AI で作ったアプリを公開する前に、秘密情報や危険な公開設定を確認する Windows アプリです。**

AI やバイブコーディングでアプリを作った人が、公開する前に「よくある公開事故」（秘密のキーの書き忘れ・Git の履歴に残ったキー・誰でも読み書きできる設定など）がないかを、アプリのフォルダを選ぶだけで確認できます。結果は日本語で、何が問題か・次に何をすればいいかを表示します。

## 最新版をダウンロード

**Windows 版はこちらからダウンロードできます → [最新版をダウンロード](https://github.com/nionxx-lab/koukai-check/releases/latest)**

開いたページの「Assets」から `.exe` のファイルをダウンロードしてください（起動のしかたは「[ダウンロードと起動](#ダウンロードと起動)」を参照）。
現在の Windows 版はコード署名をしていないため、SmartScreen の警告が表示される場合があります。

> **はじめにお読みください**
> - **完全な安全を保証するツールではありません。** よくある公開事故の決まった形を探すだけです。問題が表示されないことは、安全の保証ではありません。
> - **高度な脆弱性スキャナではありません。** コードの脆弱性をすべて解析するものではありません（認証のない API・依存パッケージの脆弱性・CORS などは確認しません）。
> - **Git が入っていなくても使えます。** その場合は、Git の履歴のチェックだけを飛ばします。
> - **Supabase のオンライン診断以外の主なチェックは、オフラインで使えます。**

## できること

アプリのフォルダの中を読んで、次のような「公開すると困ること」を探します。

- **秘密のキー・トークンの直書き**：Stripe・AWS・Supabase の secret / service_role・OpenAI・Anthropic（Claude）・GitHub などの秘密のキーが、ソースコード・設定ファイル・公開用の環境変数（`NEXT_PUBLIC_` など）に書かれていないか
- **Git の履歴に残った秘密情報**：いまのファイルから消していても、過去のコミットに残っていないか（push 済みかどうかも表示）
- **秘密鍵・サービスアカウント鍵のファイル**：中身から秘密鍵だと確認できるファイルが、Git で公開されないか
- **公開フォルダへの混入**：`public/`・`static/` などに、`.env`・秘密鍵・データベースのバックアップなどが入っていないか
- **Firebase のセキュリティルール**：「誰でも読み書きできる」ルールのままになっていないか（このPCの中のルールファイルを確認します）
- **`.env` が Git に入ってしまわないか**
- **Supabase のデータベース設定**（利用者が開始した場合だけ）：Supabase 公式の Security Advisor の結果を、分かりやすく表示します（RLS が無効なテーブルなど）

結果は「🔴 公開前に確認・修正」「🟠 確認をおすすめ」などに分けて表示します。

### 見つかった問題の直し方（修正ガイド）

- **結果のまとめ**：画面の上に「公開前に直すもの」「確認をおすすめ」の件数と一覧を出します。一覧から各項目へ移動できます。
- **直し方**：🔴・🟠 の項目ごとに、上から順に進められる手順（3〜5ステップ）を表示します。秘密のキーが漏れた可能性がある場合は、コードから消すだけでなく、**キーの無効化・作り直しを最初に**案内します。本物かどうか・公開してよいかを、あなたが判断する必要がある項目は分けて示します。
- **AIに修正を頼む**：Claude Code・Codex・Cursor などにそのまま貼り付けられる修正依頼文をコピーできます（「指示の内容を見る」で中身を確認できます）。依頼文には、**秘密の値・パソコンのフォルダの場所・ユーザー名は入れません**。キーの作り直しや Git の履歴の書き換えなど、AI に任せずにあなた自身が行う操作も、依頼文に書いてあります。依頼文は決まった文面から作るので、AI のサービスへの通信はしません。
- **もう一度チェック**：直したら「修正したら、もう一度チェックする」を押すと、同じフォルダをもう一度チェックします。

Supabase の診断でも、指摘ごとに、Claude Code や Codex などの AI にそのまま渡せる修正依頼文をコピーできます。

## しないこと

- **ファイルを書き換えません。** フォルダの中身は読むだけです。Git の履歴も書き換えません。
- **自動で直しません。** データベースや Supabase の設定も変更しません。
- **秘密の値を表示しません。** キー・トークン・秘密鍵の中身は、画面・ログ・保存するレポートのどこにも出しません（ファイル名と行番号だけを表示します）。
- **作者のサーバーへ何も送りません。** ソースコード・認証情報・診断結果を送信しません。作者のサーバー自体を使っていません。
- **テレメトリ（利用状況の送信）・解析ツール・クラッシュレポートはありません。広告もありません。アカウント登録も不要です。**

詳しくは [PRIVACY.md](PRIVACY.md) を参照してください。

## オフラインでできること・通信が必要なこと

| 機能 | 通信 |
|---|---|
| フォルダのチェック（秘密情報・秘密鍵・公開フォルダ・Firebase のルールファイル・`.env`） | **しません**（このPCの中だけで行います） |
| Git の履歴のチェック | **しません**（このPCにある履歴だけを読みます。リモートから取得もしません） |
| Supabase のオンライン診断（「Supabase のチェックを始める」を押し、接続の確認で「接続して診断する」を選んだ場合だけ） | Supabase 公式の API（`https://api.supabase.com`）へ、あなたが入力したアクセストークンで問い合わせます |
| 画面のリンク（公式ドキュメント・トークンの作成ページ） | 押した場合だけ、既定のブラウザでそのページを開きます（Supabase・Firebase・Expo・Next.js の公式サイトだけ） |

画面は、このPCの中（`http://127.0.0.1`）でだけ表示します。外部の画像・フォント・解析ツールは読み込みません。
画面の表示に使う Windows の部品「Microsoft Edge WebView2」は、Windows の設定に従って Microsoft と通信することがあります（更新・診断データなど）。koukai-check 自身には、診断するファイルや診断結果を Microsoft へ送る処理はありません。

## 必要なもの

- Windows 10 / 11（x64）。Node.js などのインストールは不要です。
- **Git の履歴のチェック**：このPCに Git（Git for Windows など）が入っている場合だけ行います。**Git がなくてもアプリは使えます。** その場合は、Git の履歴のチェックだけを飛ばし、「Git の履歴はチェックしていません」と表示します。
- **Supabase のオンライン診断**：Supabase のアクセストークン（下の「トークンの作り方」を参照）。使わない場合は不要です。

## ダウンロードと起動

1. GitHub の [Releases](https://github.com/nionxx-lab/koukai-check/releases) から `koukai-check-<バージョン>-win-x64.exe` と `SHA256SUMS.txt` をダウンロードします。
2. （おすすめ）ファイルが正しいかを確かめます。PowerShell で次を実行し、表示された値が `SHA256SUMS.txt` の値と同じなら正しいファイルです。
   ```powershell
   Get-FileHash .\koukai-check-<バージョン>-win-x64.exe -Algorithm SHA256
   ```
3. ダブルクリックします。「Windows によって PC が保護されました」と表示された場合は、「詳細情報」→ アプリ名を確認 →「実行」を押してください（まだ電子署名がないため表示されます）。
4. 「公開前チェック」のウィンドウが開きます（黒い画面やブラウザは開きません）。

画面の表示に使う「Microsoft Edge WebView2 ランタイム」は、Windows 11 には最初から入っています。ない場合は、起動時に入手方法を案内します。
初回の起動時に、画面の部品を `%LOCALAPPDATA%\koukai-check\` に置きます（診断結果は保存しません）。使わなくなったら、このフォルダごと削除してかまいません。

## 使い方

1. **「チェックするアプリのフォルダを選ぶ」**を押して、アプリのフォルダ（package.json が入っているフォルダ）を選びます。
2. 使っている技術を自動で調べて、そのアプリに必要なチェックの結果を表示します。
3. Supabase を使っている場合は、「Supabase のチェックを始める」から、データベースの設定も確認できます（アクセストークンが必要です。画面の案内に沿って作成してください）。
4. 使い終わったら「終了する」を押すか、ウィンドウの × で閉じます。

## トークンの作り方（Supabase のオンライン診断・おすすめの最小権限）

画面（「Supabase のチェックを始める」）で、4つのステップに分けて案内します。要点は次のとおりです。

1. 画面の「Supabase の作成ページをブラウザで開く」を押します（https://supabase.com/dashboard/account/tokens が開きます）。
2. 新しいトークンを作成し、次の3つを選びます。
   - 対象のプロジェクト：**診断したいプロジェクトだけ**
   - 権限：「Project」の中の **「Advisors」を「Read」だけ**
   - 有効期限：**できるだけ短く**（「無期限」は選ばない）
3. 表示された `sbp_` で始まる文字列を、画面の欄に貼り付けます。形の間違い（空白・別の鍵・途中切れなど）は、貼り付けた時点で知らせます。

アクセストークンは保存しません。使い終わったトークンは、同じ Supabase の画面から削除できます。
Scoped Token をまだ使えないアカウントでは、従来のトークン（Legacy）でも動きます。ただし権限が広いため、警告を表示します。

## ダウンロードしたファイルの確かめ方

Windows の exe は、GitHub Actions でこのリポジトリのソースからビルドし、GitHub の Releases で配布します（exe はリポジトリにはコミットしていません）。

- `SHA256SUMS.txt`：配布するファイルすべての SHA256 と、ビルドしたソースのコミット
- `BUILD-INFO.txt`：ビルドしたソースのコミット・GitHub Actions の実行・使った Node.js やコンパイラの版
- build provenance（ビルドの証明）：GitHub CLI で、このリポジトリの GitHub Actions で作られたことを確かめられます
  ```
  gh attestation verify koukai-check-<バージョン>-win-x64.exe -R nionxx-lab/koukai-check
  ```

## よくある質問

**Q. 何も問題が表示されなければ安全ですか？**
A. いいえ。このツールは、よくある公開事故の決まった形を探すだけです。すべての問題を見つけられるわけではありません。アプリの動き・認証・データの扱いは、ご自身でも確認してください。

**Q. 自動で直してくれますか？**
A. いいえ。ファイル・Git の履歴・データベースの設定は一切変更しません。表示される内容や修正依頼文を、AI や開発者に渡して、確認しながら直してください。

**Q. 秘密のキーが Git の履歴に残っていると表示されました。どうすればいいですか？**
A. まず、そのキーを発行したサービスの管理画面で、キーを無効にして作り直してください。作り直せば、履歴に残った古いキーは使えなくなります。履歴から消すには履歴の書き換えが必要ですが、このツールは行いません。

**Q. Git が入っていない PC でも使えますか？**
A. 使えます。Git の履歴のチェックだけを飛ばし、ほかのチェックはすべて行います。

**Q. macOS や Linux で使えますか？**
A. いまは Windows 版だけを配布しています。開発者の方は、下の「ソースから動かす（開発者向け）」の方法で動かせます。

## ソースから動かす（開発者向け）

Node.js 22 以上が必要です。npm には公開していません。

```bash
npm ci
npm test          # 型の確認とテスト
npm start         # 画面を起動する（既定のブラウザで開きます）
npm run build:win # Windows の exe を作る（MinGW-w64 が必要。docs/windows-exe.md）
```

ターミナルで Supabase の診断だけを行う開発用の CLI もあります（`node dist/cli/index.js supabase`。`npm start` などで一度ビルドしてから）。
アクセストークンは、実行後の入力欄に貼り付けてください（入力した文字は表示されません）。コマンドの引数や、シェルの履歴に残る書き方でトークンを渡さないでください。

配布の手順は [docs/release-windows.md](docs/release-windows.md)、変更の履歴は [CHANGELOG.md](CHANGELOG.md) を参照してください。
