# CLAUDE_CODE_OAUTH_TOKEN を秘密情報の候補として検出する

実施日: 2026-10-08
きっかけ: 作者が使っていたアプリで、`CLAUDE_CODE_OAUTH_TOKEN` を使う構成があった。

## 判断：検出対象に含める

`CLAUDE_CODE_OAUTH_TOKEN` は、`claude setup-token` で作る Claude Code の認証トークンで、自分の Claude のアカウントで Claude Code を動かすためのもの（GitHub Actions などで使う）。
漏れると、他人がそのアカウントで Claude Code を使えるおそれがあるため、API キーと同じく秘密情報として扱うべきと判断した。

## 修正前の状態

| 場所 | 修正前 |
|---|---|
| `.env` 系 | 名前に「CLAUDE」を含むため「外部のAPI（Anthropic）」として一般的な案内に出るだけで、秘密情報としては扱っていなかった。公開用の接頭辞付き（`NEXT_PUBLIC_…`）で値が `sk-ant-` の形の場合だけ、値の形から危険と判定していた |
| 設定ファイル | 調べていなかった |
| ソースコード | 調べていなかった |

### 判定の方針

| 状況 | 判定 |
|---|---|
| 参照だけ（`process.env.〜`・`Deno.env.get(…)`・`os.environ[…]`・`${{ secrets.〜 }}`・`$〜` など） | 🔴・🟠の根拠にしない。別のカードの折りたたみ「参照している場所 ○件」に出すだけ |
| ダミー・テスト用の値 | 🔴・🟠の根拠にしない。折りたたみ「テスト用・ダミーの値と判断した場所 ○件」（理由つき） |
| 本物らしい値が、Git で管理されている（tracked）・まだ追加していないが除外もされていない（untracked）ファイル、または公開用の接頭辞付きの変数にある | 🔴 |
| 本物らしい値が、Git の対象外（ignored）の .env 以外のローカルファイル、または Git なしのフォルダにある | 🟠 |
| 本物らしい値が、Git の対象外の .env にある | 問題として数えない（本来の置き場所） |

🔴・🟠のカードのタイトルに件数を出す（例：「Claude Code の認証トークンが1か所に直接書かれている可能性があります」）。

### 値の分類（値は表示しない。分類と理由だけを表示する）

| 分類 | 条件 |
|---|---|
| 本物のトークンの形式に見える | `sk-ant-` で始まり、本体が40文字以上で、大文字・小文字・数字を含み、ランダムな文字列（文字の偏りが小さく、同じ文字の繰り返しや 1234・abcd がない）。テスト用の語を含まない |
| テスト用の値（実値に似せたもの） | `sk-ant-` の形だが、TEST・FAKE・DUMMY・MOCK・EXAMPLE・SAMPLE・CANARY・FIXTURE・REDACTED などの語を含む／本体が40文字未満／ランダムではない |
| ダミー | トークンの形式ではない（空・`your-token`・`xxxx`・`<…>`・`***`・`test-token` など） |

**フォルダ名（tests・test-results など）では判断しない。** tests の中でも、本物らしい値は🔴・🟠になる。

### Git の状態の判定（直した点）

- **`.git/index` を直接読み**、Git が管理しているファイルかを判定するようにした（git コマンドは使わない。index の形式 2・3・4 に対応し、`git ls-files` と一致することを確認）。`.gitignore` に書かれていても、コミット済みのファイルは「Git で管理されている（公開される）」と判定する。
- **`.gitignore` のフォルダ指定（例：`test-results/`）が、その中のファイルに効いていなかった不具合を直した。** 以前は `test-results/claude-runner-canary.json` が、`.gitignore` に `test-results/` が書かれていても「Git の対象」と判定されていた可能性がある。
- 自動で作られるファイルが入りやすいフォルダ（test-results・coverage・playwright-report など）の中なら「自動で作られるフォルダの可能性」と添える。ただし判定は Git の状態だけで行い、生成物だからといって除外しない。
