# 持ち越し（今後の改善）

ここに書くのは「いまは直さないと決めたもの」だけです。直したものはここから消し、決めた理由を残します。

## テスト：修正ガイドの網羅性の確かめ方（LOW・0.2.0 のレビューで指摘）

- **現状**：`test/fix-guide.test.ts` の「🔴・🟠 になりうる項目のすべてに直し方がある」は、`src/checks/build.ts` のソースを文字列として読み、`id: '…'` の直後の `status: 'danger' | 'warn'` を正規表現で拾って、対象の項目（0.2.0 時点で固定の13種類と、サービスごとの秘密情報）を集めています。
- **弱いところ**：項目の書き方（`id` と `status` の並び・改行）を変えると、正規表現が拾えなくなり、対象から漏れても気づきにくい。件数の下限（11件以上）と、定義の取り残しの確認で一部は止まるが、完全ではない。
- **いま直さない理由**：0.2.0 の時点では、すべての 🔴・🟠 の項目に直し方があることを、この確認と、実際のフォルダを使った確認（`messyProject`）・実機の確認で確かめられている。テスト基盤を大きく変える必要はない。
- **直すなら**：`src/checks/build.ts` の 🔴・🟠 の項目のIDを、コードの中の一覧（定数）として持ち、`buildChecks` とテストの両方がその一覧を使う。あるいは、すべての項目を出すフィクスチャを用意し、実際に `buildChecks` を通して確かめる。
