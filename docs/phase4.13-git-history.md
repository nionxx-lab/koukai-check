# Phase 4.13：Git の履歴に残った秘密情報のチェック

実施日: 2026-10-11
範囲: いまのファイルから消えていても、過去のコミットに残っている秘密情報を見つける。**このフェーズで MVP の診断機能を凍結する**（以後、新しい診断機能は追加しない）。

実装：`src/detect/git-history.ts`（履歴の読み取り）、`src/checks/build.ts`（画面の項目）

## 1. 何を調べるか

- すべての参照（ブランチ・タグ・リモート追跡ブランチ・stash）から届くコミットに含まれる、ファイルの各版（blob）
- そのうち、いまのファイルと同じ種類のもの：`.env` 系・設定ファイル・ソースコード・鍵ファイルの候補。`node_modules` などは除く
- 判定は、いまのファイルと**同じ仕組み**：秘密情報の定義（`secret-defs.ts`。Stripe・AWS・Supabase・GitHub など）と、秘密鍵・サービスアカウント鍵の判定（`key-files.ts`）
- 選んだフォルダがリポジトリの一部（モノレポ）なら、その中のパスだけ

## 2. 🔴・🟠 の条件

| 状況 | 判定 |
|---|---|
| 本物らしい値・本物の形の鍵が、**push 済み**のコミット（リモート追跡ブランチから届く）に残っている | 🔴 |
| まだ push していないコミット・リモートがないリポジトリに残っている | 🟠（push すると公開される。push 前に対処できる） |
| 本物か判断できない値（ローカル開発用の Supabase の鍵の形など）・パスフレーズで暗号化された鍵 | 🟠 |
| テスト用・ダミー・公開してよいキー（Stripe の `pk_`・Supabase の publishable など）・参照だけ | 数えない |
| **いまのファイルにもある値** | 履歴では数えない（いまのファイルの項目で知らせる） |
| 何も見つからない | ✅（確認したコミット数・ファイルの版の数） |

各項目には、種類・ファイル名・その版を最初に含んだコミット（短い SHA と日付）・push 済みか・同じ値がほかに何か所あるかを出す。値は出さない。

対処の案内：まずキー・鍵を無効にして作り直す（履歴に残った古い値は使えなくなる）。履歴から取り除くには `git filter-repo` などで履歴を書き換える必要がある。**このツールは履歴を書き換えない・自動で直さない。**

## 3. 同じ秘密情報を重ねて出さない

- 同じ値かどうかは、**実行のたびに乱数で作って捨てる鍵の HMAC-SHA256** で比べる。値も指紋も、結果・画面・ログには入れない（鍵は終わったら 0 で塗りつぶす）
- 同じ値が複数のファイル・複数のコミットにあれば、1件にまとめて「同じ値がほかに N か所」と出す
- いまのファイルの値も同じ方法で指紋にし、履歴の結果から除く
- 中身がまったく同じファイルは Git の中で1つの版（blob）なので、1か所として数える

## 4. 上限

| 上限 | 既定 |
|---|---|
| 調べるファイルの版の数 | 20,000 |
| 合計の大きさ | 64MB |
| 1つの版の大きさ | 1MB（これより大きい版は調べない） |
| 全体の時間 | 20 秒 |
| 知らせる件数 | 50 |

上限に達したら「履歴が大きいため、一部だけを確認しました」と伝える。

## 5. Git が使えないとき

| 状況 | 動き |
|---|---|
| Git で管理していないフォルダ・`.git` が壊れている | 履歴の項目を出さない |
| このPCで git が見つからない | 📘「Git の履歴はチェックしていません」。ほかのチェックは通常どおり |
| 一部だけを取得したリポジトリ（partial clone）・安全のための設定（持ち主の違うフォルダ）で読めない・時間内に読めない・読み取りエラー | 📘「Git の履歴はチェックできませんでした」と理由。ほかのチェックは通常どおり |

アプリ全体は失敗させない。

## 6. 安全のため

- git は **PATH から絶対パスで**探す。調べるフォルダの中・相対パスの PATH の git は使わない（Windows は、作業フォルダに置かれた `git.exe` を先に実行してしまうことがあるため。悪意のあるリポジトリを想定）
- 使うコマンドは `rev-list`・`cat-file`・`log --find-object`・`for-each-ref`・`branch -r --contains` だけ（実行前に一覧で確かめる）。履歴・設定・作業ファイルを書き換えるコマンドは使わない。静的監査のテストでも確かめる
- `GIT_DIR` などの環境変数を消し、別のリポジトリに向けられないようにする。`GIT_TERMINAL_PROMPT=0`（入力を求めない）・`GIT_OPTIONAL_LOCKS=0`（ロックを作らない）・`core.fsmonitor=false`
- 中身の差分を作る処理（`log -p` など。textconv・外部 diff が動く）は使わない
- **通信しない**：一部だけを取得したリポジトリ（partial clone）では、手元にないファイルの版を git が自動でリモートから取りに行く。`GIT_NO_LAZY_FETCH=1` でこれを止め、さらに `.git/config` から partial clone と分かったら履歴を読まずに 📘 で理由を出す（この変数を知らない古い git のため。公開前の監査で見つけて直した）
- シェルを使わず、Windows では窓を出さずに（`windowsHide`）起動する
- テストで、`.git` の中のファイルが実行の前後で変わらないことを確かめる

## 7. 意図的に検出しないもの

- 到達できないオブジェクト（どの参照からも届かない古いコミット・reflog だけにあるもの）
- 1MB を超えるファイルの版・バイナリ
- 調べる種類以外のファイル（画像など）
- コミットメッセージ・ブランチ名に書かれた値
- リモートにだけあり、手元に取得していないコミット（`git fetch` はしない）
