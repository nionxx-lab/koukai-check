# Phase 4.8：Supabase のアクセストークン作成を、初心者向けにする

実施日: 2026-10-08
範囲: `docs/next-token-onboarding-design.md` の **A（4ステップの案内）＋ B（貼り付け時の確認と、エラーごとの直し方）** を実装した。
OAuth（案 D）は実装していない（ローカルで配布するアプリでは client secret を安全に持てないため）。新しい診断項目は追加していない。

## 調査：作成画面を、選択済みの状態で開ける公式の仕様はあるか（案 C）

**結論：公式の仕様は見つからなかった。そのため実装していない**（推測の URL パラメータは使わない）。

| 調べたもの | 結果 |
|---|---|
| Supabase 公式ドキュメント「Personal Access Tokens」（`apps/docs/content/guides/platform/personal-access-tokens.mdx`、GitHub の supabase/supabase の master） | 作成方法は「アクセストークンの設定（`/dashboard/account/tokens`）から作る」とだけ書かれている。名前・対象・権限・期限を URL で指定する方法の記載はない |
| 同ドキュメントの権限一覧（`_partials/access-control/scoped_pat_permissions.mdx`） | **「Project」グループの「Advisors」― Read** で、Get security advisors が使えると記載されている（画面の案内はこの表記に合わせた） |
| Web 検索（公式ドキュメント・GitHub の議論・第三者の解説） | 作成画面のパラメータを説明したものはない。OAuth の認可画面には組織を事前に選ぶ `organization_slug` があるが、トークンの作成画面とは別のもの |

範囲を絞ったトークン（scoped）は、公式ドキュメントでは段階的に公開中とされている。権限を選ぶ画面が出ないアカウントでは、従来型（Legacy）しか作れない場合がある。

## 実装したこと

### A. アプリ内の4ステップの案内（`src/app/pages.ts` の `supabaseTokenPage`）

| ステップ | 内容 |
|---|---|
| 1. これから何をするか | 「トークン」を前提にせず、**「診断結果を見せてもらうための専用の合言葉」**として説明してから、Supabase の画面での名前（アクセストークン）を示す。できるのは診断結果を読むことだけ・保存しない・作者のサーバーに送らない |
| 2. Supabase で作る | **「Supabase の作成ページをブラウザで開く」ボタン**（専用ウィンドウでは既定のブラウザで開く）。選ぶものを3つに絞って具体的に案内：① **対象のプロジェクト**（設定ファイルで見つけたプロジェクトIDを表示）② **「Project」の中の「Advisors」を「Read」**、ほかの権限は付けない ③ **有効期限はできるだけ短く**、「無期限（Never）」は選ばない。作成直後に一度だけ表示される文字列を閉じる前にコピーすること。**Legacy はおすすめしない** |
| 3. 貼り付けてチェックする | パスワード欄（値は画面に戻さない）。貼り付けた瞬間に確認結果を表示する（B） |
| 4. 使い終わったら削除する | 同じページで削除できること、期限を短くすれば消し忘れても使えなくなること。削除のページを開くボタン |

レポートの末尾にも、使い終わったトークンを削除できることを書き添えた。

### B. 貼り付け時の確認（`src/supabase/token-check.ts` の `checkTokenInput`）

画面（貼り付けた瞬間）と、サーバー（「チェックする」を押したとき）で**同じ関数**を使う（画面にはこの関数のソースをそのまま埋め込む）。**Supabase への問い合わせはしない。** 結果のメッセージにはトークンの文字を含めない。

| 種類 | 例 | 扱い |
|---|---|---|
| 自動で直す | 前後・途中の空白や改行、全角文字、ゼロ幅文字、引用符、先頭の「Bearer」「SUPABASE_ACCESS_TOKEN=」 | 取り除いて、直したことを表示 |
| エラー（送らない） | 未入力／省略表示（… ●）のコピー／`eyJ…`（anon key・service_role key）／`sb_publishable_`・`sb_secret_`（API キー）／URL／プロジェクトID／`sbp_` で始まらない／使えない文字 | 何を貼るべきかを表示し、「チェックする」を止める（サーバー側でも止める） |
| 注意 | 従来型（Legacy、`sbp_` だが `sbp_fc` でない） | おすすめしない理由と作り直し方を表示。**「理解したうえで続ける」に印を付けない限り使わない**（サーバー側でも確認） |
| 注意 | 短すぎる（途中で切れている可能性） | 確認を促す（送ることはできる） |

### B. 問い合わせが失敗したときの直し方（`src/app/token-guide.ts`）

| 応答 | 表示する直し方 |
|---|---|
| 401（無効） | コピーの途中切れ／作成画面を閉じて全文が分からない場合は作り直す／削除・期限切れなら作り直す |
| 403（権限不足） | 「Advisors」を「Read」にしたか／対象のプロジェクト（**ID を表示**）を選んだか／アカウントがそのプロジェクトのメンバーか |
| 404（見つからない） | 対象のプロジェクトの選び間違い（対象に含めていないと「見つからない」と返ることがある）／URL の貼り間違い／プロジェクトの一時停止・削除 |
| そのほか（通信・混雑・障害など） | 従来の説明 |

対象外のプロジェクトを問い合わせたときに 403 と 404 のどちらが返るかは公開されていないため、両方で「プロジェクトの選び間違い」を案内している。実際の応答は `manual-e2e-check.md` の 5-1〜5-4 で記録できる。

## 変えていないこと

- トークンは保存しない・ログに出さない・URL や画面に戻さない・作者のサーバーへ送らない（テストで確認）。
- 通信先は `https://api.supabase.com` だけ。専用ウィンドウ・既存の診断・フォルダの解析・開発用の CLI はそのまま。

## テスト

`npm test`：**280件すべて通過**（Node 22.22.0）。追加・変更：
- `test/token.test.ts`（新規）：貼り付け時の確認（自動で直す・エラー・Legacy・短すぎる・メッセージにトークンを含まない・画面に埋め込んだソースが同じ結果になる）、4ステップの画面（用語の説明の順番・作成ページのボタン・3点の案内・Legacy の確認欄）、401／403／404 の直し方。
- `test/app.test.ts`：形の間違ったトークンでは Supabase に問い合わせない／空白を取り除いて問い合わせる／Legacy は確認の印がないと使わない／403・404 の直し方の表示。
- ブラウザ（Chromium）での確認：貼り付けた瞬間の表示、空白の自動除去、Legacy の確認欄、エラー時に送信しないこと、403 の直し方の表示。コンソールのエラーなし（CSP の範囲内で動く）。
