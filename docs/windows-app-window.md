# Phase 4.7：Windows の専用アプリウィンドウ（WebView2）で表示する

実施日: 2026-10-08
範囲: Phase 4.6 の起動方式（exe → 黒いコンソール画面 → 既定のブラウザで localhost を開く）を、
**「公開前チェック」という名前の専用ウィンドウの中に画面を表示する方式**に変えること。診断機能は追加していない。

## 方式の比較と決定

| 基準（優先順） | **WebView2 ＋ 小さなネイティブのウィンドウ（採用）** | Tauri | Electron | Edge の `--app` モード |
|---|---|---|---|---|
| 1. 追加インストールなし | ◎ exe 1つ。Windows 11 には WebView2 が標準で入っている。Windows 10 も、Edge の更新で大半に入っている | ◎ 同じ（WebView2） | ◎ Chromium を同梱 | ◎ Edge は標準 |
| 2. 配布サイズ | ○ **82.5MB**（Node.js 本体 ＋ 300KB のウィンドウ ＋ 161KB の公式ローダー） | ◎ 数MB（ただし Node.js 部分を Rust で作り直すか、別の exe を同梱する必要がある） | × 展開後 200MB 以上。1ファイルにすると起動のたびに一時フォルダへ展開する | ◎ 増えない |
| 3. WebView ランタイムへの依存 | △ WebView2 Evergreen ランタイムが必要（ない場合は案内を表示） | △ 同じ | ◎ 依存しない | △ Edge に依存 |
| 4. 署名前の SmartScreen / Defender | ○ SmartScreen の警告は exe 1つ分だけ（初回）。中の部品は %LOCALAPPDATA% に置くが、Microsoft 署名の DLL と 300KB の exe だけ | ○ 同程度 | △ 大きな未署名ファイル群。portable 形式は「自己展開」として誤検知されやすい | ○ |
| 5. 既存の Node / HTML の再利用 | ◎ **そのまま**（サーバー・画面・診断・CLI を変えていない） | × Node.js 部分の作り直し、または sidecar の管理が必要 | ◎ そのまま | ◎ そのまま |
| 6. フォルダ選択の画面を手前に出す | ◎ **ウィンドウ自身が親になってフォルダ選択を出す**（同じプロセス・同じ窓が親なので、裏に隠れない） | ◎ 同じ | ◎ 同じ | × 別プロセス（PowerShell）から出すしかなく、ブラウザの裏に隠れうる |
| その他 | ビルドに MinGW-w64 が必要（作者側だけ） | Rust の Windows 向けクロスビルドが必要 | 更新・監査の負担が大きい | **ブラウザそのもの**。開発者ツール（F12）・任意のURLへの移動・印刷などを止められない。要件を満たさない |

**決定：Node.js SEA（今までの exe）＋ WebView2 を表示する小さなネイティブのウィンドウ（C++）。**
新しいブラウザエンジンは同梱せず、Windows の WebView2 を使う。Node.js 側（フォルダの解析・Supabase 診断・安全対策・CLI）はそのまま使う。

## しくみ

```
koukai-check-0.1.0-win-x64.exe（Node.js SEA。「ウィンドウのアプリ」なので黒い画面は開かない）
 ├─ 127.0.0.1 だけで待ち受けるサーバーを起動（今までと同じ。/r/<128ビットの乱数>/）
 ├─ exe の中の部品を %LOCALAPPDATA%\koukai-check\window\<内容のハッシュ>\ に置く（SHA256 で照合）
 │    koukai-check-window.exe（専用ウィンドウ。native/windows-host/host.cpp）
 │    WebView2Loader.dll（Microsoft 公式。WebView2 SDK 1.0.4129.50）
 └─ 専用ウィンドウを起動し、標準入出力でやり取りする
       Node.js → ウィンドウ： NAVIGATE <url> / PICK / OPEN-EXTERNAL <url> / QUIT
       ウィンドウ → Node.js： READY / PICKED <path> / PICK-CANCELLED / EXTERNAL <url> / NO-RUNTIME / CLOSED など
```

- 表示する URL は、コマンドラインではなく標準入力で渡す（他のプロセスから見えにくくするため）。
- 「チェックするアプリのフォルダを選ぶ」を押すと、サーバーが PICK を送り、**専用ウィンドウが自分を親にしてフォルダ選択の画面（Windows 標準の IFileOpenDialog）を出す**。結果を Node.js に返し、今までどおり解析する。
- 「終了する」→ サーバーが QUIT を送る → ウィンドウが閉じる → サーバーを止めてプロセスが終わる。
- ウィンドウの × で閉じた場合も、ウィンドウが CLOSED を送って終わる → サーバーを止めてプロセスが終わる。
- Node.js 側が落ちた場合は、標準入力が閉じるので、ウィンドウも閉じる（画面だけが残らない）。
- PowerShell のフォルダ選択と既定のブラウザは、**exe 版では使わない**（`npx koukai-check` の場合だけ使う）。

## 安全のための設定（専用ウィンドウ）

| 項目 | 設定 |
|---|---|
| 表示してよいページ | 最初に渡された `http://127.0.0.1:<port>/r/<乱数>/` で始まるページだけ。それ以外への移動（リンク・リダイレクト・iframe）はすべて止める |
| 外部リンク | 止めたうえで Node.js 側に問い合わせ、**画面に出している公式ドキュメント（https の supabase.com とそのサブドメイン・firebase.google.com・docs.expo.dev・nextjs.org）だけ**を既定のブラウザで開く。ウィンドウ側でも https・空白や引用符なしを再確認する |
| 新しいウィンドウ | 開かない（target="_blank" のリンクも上と同じ扱い） |
| 開発者ツール | 無効（F12・Ctrl+Shift+I・右クリックの「検証」も出ない） |
| ブラウザのショートカット | 無効（F5・Ctrl+P・Ctrl+F・Alt+← など）。コピー・貼り付けなどの編集操作は使える |
| 右クリックメニュー | 切り取り・コピー・貼り付け・すべて選択だけを残す（戻る・印刷・名前を付けて保存などは出さない） |
| URL 入力 | アドレスバーがないので、そもそもできない |
| ページから呼べる機能 | なし（host object・web message を無効化。ページの JavaScript からウィンドウやPCの機能を呼べない） |
| 許可の要求 | カメラ・位置情報・通知などは、すべて自動で断る |
| ファイルのドロップ | 無効（ドロップしたファイルにページが切り替わらない） |
| パスワード保存・自動入力 | 無効（トークンの欄を保存させない） |
| 閲覧データ | InPrivate モード（キャッシュなどをディスクに残さない）。ページ自体も `Cache-Control: no-store` |
| URL の評価（SmartScreen） | 無効（表示するのは 127.0.0.1 だけなので、Microsoft に URL を問い合わせない） |
| 「HTMLとして保存」 | ダウンロード一覧は出さず、このウィンドウの「名前を付けて保存」画面で保存先を選ぶ。アプリの画面以外からのダウンロードは止める |
| DLL の読み込み | System32 と、明示したパス（同じフォルダの WebView2Loader.dll）からだけ |
| 直接起動された場合 | 「このファイルは部品です」と表示して終わる（標準入力が Node.js からのパイプでない場合） |

Node.js 側の安全対策（127.0.0.1 だけで待ち受け・推測できないパス・Host ヘッダーの検査・Origin と csrf の確認・CSP・トークンを保存しない など）は Phase 4 から変えていない。

## プライバシー

- このツールが通信するのは、今までどおり `https://api.supabase.com`（Supabase のチェックを行ったときだけ）と、PC の中の 127.0.0.1 だけ。作者のサーバーへの送信・解析・テレメトリはない。
- 画面の表示に使う WebView2 は Windows の部品（Microsoft Edge と同じもの）で、Windows の「診断データ」の設定に従って Microsoft に診断データを送ることがある。これは Windows / Edge 側の動きで、このツールからは止められない。このツールは、URL の評価（SmartScreen）の問い合わせは無効にしている。
- 初回の起動時に、`%LOCALAPPDATA%\koukai-check\` に画面の部品（window\）と WebView2 の作業用フォルダ（WebView2\）を作る。診断結果・トークンは保存しない。

## 起動後の流れ（利用者から見えるもの）

1. exe をダブルクリックする（初回だけ SmartScreen の警告が出ることがある）。
2. 「公開前チェック」のウィンドウが、画面の中央に開く（数秒「起動しています…」と表示されることがある）。**黒い画面もブラウザも開かない。**
3. 最初の画面は「チェックするアプリのフォルダを選ぶ」。
4. 押すと、ウィンドウの手前に「チェックするアプリのフォルダを選んでください」の画面が開く。
5. 選ぶと、同じウィンドウの中にチェック結果が表示される（Supabase を使っていれば「Supabase のチェックを始める」も出る）。
6. 公式ドキュメントへのリンクは、既定のブラウザで開く。
7. 「終了する」か × で、ウィンドウもツールも終わる（タスクマネージャーに残らない）。

## ビルド（作者側）

```bash
sudo apt install g++-mingw-w64-x86-64-win32 binutils-mingw-w64-x86-64   # Ubuntu の例
cd koukai-check
npm install
npm run build:win
```

- WebView2 SDK は nuget.org から取得し、**版（1.0.4129.50）と SHA256 を固定して照合**する（`scripts/build-windows-exe.mjs` の `WEBVIEW2_SDK`）。
- exe のアイコンとバージョン情報を「公開前チェック」にする（`resedit`。開発時だけ使う。配布物の実行には不要）。アイコンは `scripts/make-icon.mjs` で作っている。
- PE の Subsystem を 3（コンソール）から 2（ウィンドウのアプリ）に変える。
- `release/windows/THIRD-PARTY-NOTICES.txt` に Node.js と WebView2 SDK のライセンスを書き出す。
